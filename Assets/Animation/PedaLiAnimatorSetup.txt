PedaLi pixel animation setup
=============================

Runtime sprite animation is handled by Assets/Scripts/PedaLiSpriteAnimator.cs.
This frame-based animator does not require an Animator Controller.

1. Import each character sprite sheet as Texture Type = Sprite (2D and UI).
2. Set Filter Mode = Point (no filter), Compression = None, and disable mipmaps.
3. Open Sprite Editor and slice the sheet by Grid By Cell Size (or automatic slicing if frames vary).
4. Keep the same Pixels Per Unit and consistent frame dimensions for all animations.
5. Create a child object named Visual if desired. Add SpriteRenderer and PedaLiSpriteAnimator to that object.
6. Assign the SpriteRenderer to PedaLiController, and assign PedaLiSpriteAnimator to its Pixel Animator field.
7. Drag frames into each animation's Frames array in playback order. Set the FPS and Loop options.

Animation arrays:
- Idle: breathing / standing frames, looping, around 4–6 FPS.
- Run: left/right run cycle, looping, around 8–12 FPS.
- Jump: take-off / airborne frames, usually non-looping.
- Grab: hanging idle frames, looping.
- Climb: hand-over-hand upward movement, looping.
- Fall: falling pose or short loop.

State selection is driven by PedaLiController:
- Idle when grounded and not moving.
- Run when grounded and moving.
- Jump while moving upward in the air.
- Fall while moving downward in the air.
- Grab while holding a ledge without horizontal input.
- Climb while grabbing and moving horizontally (the starter controller's climb motion is upward).

The previous Animator Controller setup can still be used for additional effects, but avoid having both the Animator Controller and PedaLiSpriteAnimator animate the same SpriteRenderer.sprite property at the same time.

No sprite artwork is included yet; the animation system needs actual sliced frame sprites assigned in the Inspector.
